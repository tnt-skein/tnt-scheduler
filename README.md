# tnt-scheduler

Работы по расписанию cron в самом узле Tarantool: «в 03:00 по будням
по Москве», «каждый час», «первого числа месяца». Выражение разбирает
рок `cron-parser`, цикл `tnt-loop` остаётся фибером и тактом, а срок
считается по стенным часам в названном поясе.

```lua
local jobs = require('tnt.scheduler').new({ zone = 'Europe/Moscow' })

jobs:job('audit-export', '0 3 * * 1-5', export.flush)   -- по будням в 03:00 по Москве
jobs:start()
```

Зависимости: `tnt-loop` (цикл работы), `tnt-clock` (часы), `tnt-date`
(смещение пояса), `tnt-log` (журнал), `tnt-must` (проверки аргументов),
`tnt-metrics` (ряды запусков и пропусков), `tnt-external` (подмена часов
в проверках) и рок `cron-parser 1.0.0-1` с сервера роков Tarantool — он
собирается из одного файла C, и установке нужен компилятор. Замок
кластера приходит аргументом: подойдёт `lock.occupy` из `tnt-lock` либо
любая функция с тем же договором.

## Зачем

Снимок, вычистка устаревшего, выгрузка журнала — работы «в 3:00
по будням», а не «раз в пять секунд». Период цикла такого не скажет,
а внешний cron не знает ни какой узел сейчас пишет, ни что соседний узел
ту же работу уже сделал. Пакет держит расписание в узле:

- **Расписание — выражение cron**, разбирает его рок, а там, где рок
  молча ошибается (восьмеричные числа, склейка полей табуляцией, срок
  только от «сейчас», падение процесса на неразобранном выражении),
  фасад закрывает это сам.
- **Срок — по стенным часам в поясе**, с переводом часов по обе стороны.
- **У каждой работы свой цикл**: долгая работа держит только себя,
  а сроки, прошедшие за долгий запуск, пропускаются.
- **Итог — что вернул обработчик**: значение, `nil, err` либо исключение;
  журнал не повторяет одну и ту же беду каждую секунду.
- **`writable` и `exclusive`**: срок только на узле для записи и только
  на одном узле кластера, а замок держится не меньше `hold` секунд
  от захвата — узел, чьи часы отстают, не исполнит срок второй раз.
- **Ряды метрик**: запуски по итогу, пропуски по причине, длительность.

## Установка

```sh
tt rocks install tnt-scheduler --server=https://tnt-skein.github.io/rocks
```

Или из исходников:

```sh
git clone https://github.com/tnt-skein/tnt-scheduler.git
cd tnt-scheduler && tt rocks make --server=https://tnt-skein.github.io/rocks
```

## Как пользоваться

```lua
local lock = require('tnt.lock')
local scheduler = require('tnt.scheduler')

local jobs = scheduler.new({ occupy = lock.occupy, zone = 'Europe/Moscow' })

-- По будням в 03:00 по Москве, на одном узле кластера и только на узле для записи.
jobs:job('audit-export', '0 3 * * 1-5', function(run)
    return export.flush()
end, { exclusive = true, writable = true })

-- Раз в пять секунд на каждом узле.
jobs:job('heartbeat', '*/5 * * * * *', function()
    heartbeat.touch()
end)

jobs:start()
```

| Вызов | Что делает |
|---|---|
| `scheduler.new({ occupy, zone })` | планировщик; `occupy` — замок кластера, `zone` — пояс работ по умолчанию |
| `jobs:job(name, expression, handler, opts)` | объявляет работу; настройки — `exclusive`, `writable`, `hold`, `zone` |
| `jobs:start()`, `jobs:stop()`, `jobs:running()` | запуск и остановка всех работ |
| `jobs:status()` | состояние работ: следующий срок, счёт итогов, последний срок |
| `scheduler.parse(expression, zone)` | расписание из данных: `schedule` либо `nil, err` |
| `schedule:next(after)` | ближайший срок строго после мига, секунды UTC |

Выражение — шесть полей, секунды первыми; запись crontab из пяти полей
и слова `@daily`, `@hourly` и соседи тоже годятся. Расписание
из конфигурации — данные, и негодное отказывает парой:

```lua
scheduler.parse('0 3 * * 1-5', 'Europe/Moscow'):next(1789819200)
--> 1789948800 — понедельник, 21.09.2026 00:00 UTC

scheduler.parse('0 0 24 * * *')
--> nil, 'расписание «0 0 24 * * *» не разобрано: Specified range exceeds maximum'
```

Негодный аргумент объявления — исключение на строке вызывающего: имя
не по образцу `^[%w_.%-]+$`, незнакомый ключ настроек, работа с тем же
именем, `exclusive` без `occupy`, `hold` без `exclusive`, расписание,
которое не разобралось.

## Проверки

```sh
make deps          # luatest, luacheck, luacov с cluacov, зависимости пакета и соседи проверок
make check         # форматирование, линт, проверки, покрытие с порогом 100 %
make mutants-all   # мутационное тестирование утилитой tnt-mutants из PATH, порог 100 % убитых
```

Покрытие строк — 100 %, убитых мутантов — 100 % (99 проверок,
281 мутант в пяти модулях). Расписание проверяется настоящим роком,
часы — двойником через `_set_source`: срок наступает мгновенно, но там,
где наступил бы.
Стык с замком проверяется настоящим `tnt-lock` на двойнике хранилища
решений из `tnt-etcd-client` — оба `make deps` ставит в `.rocks`.
